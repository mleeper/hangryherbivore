# Hangry Herbivore — Management Commands Reference

## Load Order (first time setup)
Run these in order on a fresh database:

1. python manage.py load_nutrients
2. python manage.py load_ingredient_categories
3. python manage.py load_ingredients
4. python manage.py load_measurements
5. python manage.py load_blog_categories

## Recipes App

### load_nutrients
Loads the master nutrient list from fixtures/nutrients.json
- Safe to run multiple times (uses get_or_create)
- Must run before load_ingredients
python manage.py load_nutrients


### load_ingredients
Loads ingredients and nutrient profiles from:
  - fixtures/ingredients.json
  - fixtures/ingredient_nutrients.json
- Safe to run multiple times (uses update_or_create)
- Requires nutrients and ingredient categories to exist first
- Sets serving_size to 100, serving_unit to g or ml via is_liquid()
- Sets is_liquid flag based on ingredient name
python manage.py load_ingredients

### load_measurements
Loads common US to metric measurement conversions
- Safe to run multiple times (uses update_or_create)
- No dependencies
python manage.py load_measurements

### clear_ingredients
Clears the IngredientNutrientRelationship table along with the Ingredient table
- USE WITH CAUTION — destructive operation
- Run before reloading ingredient nutrient data
python manage.py clear_ingredients


## Blog App

### load_blog_categories
Loads initial blog categories
- Safe to run multiple times (uses update_or_create)
- No dependencies
python manage.py load_blog_categories

## Django Built-in Commands (useful ones)

### Migrations
# Create migrations after model changes
python manage.py makemigrations

# Apply migrations
python manage.py migrate

# Check migration status
python manage.py showmigrations

# Preview SQL a migration will run
python manage.py sqlmigrate recipes 0023

### Data Management
# Export model data to JSON (backup before bulk changes)
python manage.py dumpdata recipes.Nutrient --indent 2 > recipes/fixtures/nutrients_backup.json
python manage.py dumpdata recipes.Ingredient --indent 2 > recipes/fixtures/ingredients_backup.json
python manage.py dumpdata blog.BlogCategory --indent 2 > blog/fixtures/categories_backup.json

# Load data from fixture file
python manage.py loaddata nutrients_backup.json

# Clear expired sessions
python manage.py clearsessions

### Wagtail Specific
# Rebuild search index after bulk data changes
python manage.py update_index

# Publish pages scheduled for future dates
# (set up as hourly cron job on server)
python manage.py publish_scheduled_pages

# Wagtail fixturebird - useful for exporting page tree
# pip install wagtail-fixturebird
python manage.py fixturebird

### Development
# Start development server
python manage.py runserver

# Open Django shell
python manage.py shell

# Check for model/config errors
python manage.py check

# Collect static files (run before deploy)
python manage.py collectstatic --noinput

## Server Commands (AlmaLinux 9)

### After code or model changes
sudo systemctl restart gunicorn
sudo systemctl reload nginx

### Check service status
sudo systemctl status gunicorn
sudo systemctl status nginx

### View live logs
sudo journalctl -u gunicorn -f
sudo journalctl -u nginx -f

### Check last 50 log entries
sudo journalctl -u gunicorn -n 50

## Deploy Script
#!/bin/bash
# deploy.sh — run locally to build and push to server

echo "Building Astro..."
cd frontend && astro build && cd ..

echo "Syncing to server..."
rsync -avz --delete frontend/dist/ user@yourserver:/path/to/dist/

echo "Running migrations on server..."
ssh user@yourserver "cd /path/to/project && python manage.py migrate"

echo "Restarting services..."
ssh user@yourserver "sudo systemctl restart gunicorn && sudo systemctl reload nginx"

echo "✓ Deploy complete"

## Fixture Files Reference
recipes/fixtures/
  nutrients.json              ← master nutrient list with USDA IDs
  ingredient_categories.json  ← ingredient categories
  ingredients.json            ← ingredient names and fdcIds
  ingredient_nutrients.json   ← USDA nutrient profiles per ingredient
  validation_issues.json      ← generated by validate_ingredients (if issues found)

blog/fixtures/
  categories_backup.json      ← generated by dumpdata

## Cron Jobs (set up on server)
# Publish scheduled Wagtail pages every hour
0 * * * * /path/to/venv/bin/python /path/to/manage.py publish_scheduled_pages

# Clear sessions weekly
0 0 * * 0 /path/to/venv/bin/python /path/to/manage.py clearsessions

# Rebuild search index nightly
0 2 * * * /path/to/venv/bin/python /path/to/manage.py update_index
